# Requirements
The requirement for this project was to create an algorithm that was the best you could to play battleship against the random computer.

# Design
I started by making sure I had the RANDOM functionality working. It seemed to work by default, so I made sure the other states in the (partially) built in state machine worked in a separate manner. From there I knew I wanted SEARCH to check up down left and right for ships to then swap to DESTROY once the directionality was chosen to destroy the selected ships. I got this functionality mostly working, however the swaps between states often took a game cycle to be performed, during which the move selected was a repeated move, and thus automatically selected a RANDOM move. There were problems that arose later involving this functionality.

# Implementation
I implemented SEARCH by incrementing hitDir and then using the result of the move made to test the direction of the ship hit by the RANDOM function. I implemented DESTROY by telling it to first increment hitDist until the result was a miss, then invert hitDir and set hit Dist to 1, and repeat the functionality. This worked well, unless there was already a hit on the ship in question, as the DESTROY function originally would stop when it found a mark that wasn't empty. I'm realizing in post I needed to tell it to skip over hits. I did actually attempt to repair this but there were chaotic results I will speak on later.

# Testing
The testing phase was a bit chaotic, especially before I found the debug functionality. It usually involved me studying closely the functionality of the battle taking place, sometimes more than one battle, and trying to understand what choice was being made and why. One of the most common bugs I encountered was DESTROY getting stuck hitting the same space over and over, which cause RANDOM functionality as a result. Additionally DESTROY, as it got more complicated would also oscillate between two points, causing the same functionality.
